# Модуль Review Requests для OkayCMS

> **Лише для [форку OkayCMS](https://github.com/devSviat/OkayCMS-Fork).** Модуль
> спирається на те, чого в стоковій OkayCMS 4.5.3 немає: оцінку 1–5 у відгуку й
> рейтинг товару з відгуків (`RatingHelper`), а також механізми безпеки ядра
> форку (`CustomerCsrfToken`, `FormToken`, `AttemptLimiter`, перевірку origin).
> На стоковій OkayCMS модуль не працює.

Після виконаного замовлення модуль надсилає покупцю **один лист** із проханням
оцінити куплені товари. За посиланням із листа покупець ставить оцінку від 1 до
5 і пише відгук на кожен товар із замовлення. Відгук потрапляє у звичайні
відгуки товару: модерація, відповіді й рейтинг працюють як завжди.

Позначку **«Перевірена покупка»** отримує відгук, за яким стоїть виконане
замовлення цього товару:

- відгук, залишений за посиланням із листа: посилання одноразове й прив'язане до
  конкретної покупки;
- відгук покупця, який увійшов у кабінет і має виконане замовлення з цим товаром,
  оформлене не пізніше за відгук;
- старі відгуки — разовою дією в адмінці (вкладка «Інструменти»): збіг email
  відгуку з email виконаного замовлення цього товару, оформленого не пізніше за
  відгук. Спершу перегляд зі списком, потім підтвердження; діє один раз і лише на
  відгуки, написані до натискання, бо email у формі відгуку ніхто не перевіряє.

Якщо замовлення пізніше вийшло з «виконаного» статусу, позначка зникає.

## Можливості

### Лист

- Один лист на виконане замовлення, лише про товари з нього. Без нагадувань.
- Українською, якщо українська мова на сайті є й увімкнена; інакше — мовою
  замовлення.
- Фото й назви товарів, кнопка «Оцінити товари», посилання для відмови.
- Без пікселів відстеження.

### Захист від потоку листів

| запобіжник | типово |
| --- | --- |
| Тестовий режим після встановлення: черга будується, листи не йдуть | увімкнено |
| Замовлення, виконані до встановлення модуля, листа не отримують | завжди |
| Статус «виконане» обирає адмін; без вибору модуль нічого не робить | не обрано |
| Доданий статус: замовлення, що вже в ньому, листа не отримують | завжди |
| Затримка після виконання | 7 днів |
| Вікно відправки | 10:00–19:00 |
| Листів на добу, не більше | 40 |
| Одній адресі не частіше ніж | раз на 60 днів |
| Не писати, якщо замовленню більше | 45 днів |
| Виключені адреси й домени | — |
| Збій пошти: повтор через 1 год, потім через 24 год, далі — «помилка» | завжди |

### Відмова від листів

- Посилання в кожному листі: сторінка з кнопкою підтвердження. Поштові сканери,
  що відкривають посилання самі, людину не відпишуть.
- **Відписка в один клік** (RFC 8058, `List-Unsubscribe-Post`) — налаштування в
  адмінці, типово вимкнене. Gmail і Yahoo вимагають її від тих, хто надсилає
  понад 5000 листів на добу. Працює, коли листи йдуть через SMTP.
- **Кабінет покупця:** галочка «Надсилати мені лист із проханням оцінити товари»
  під формою профілю. Відмову за посиланням із листа кабінет не скасовує —
  адреса акаунта не підтверджена; повернути адресу може менеджер в адмінці.
- Стоп-лист зберігає лише SHA-256 адреси.

### Адмінка

Чотири вкладки:

- **Огляд** — готовність до роботи (статус, адреса сайту, режим), результати за
  30 днів (надіслано, відкрили посилання, залишили відгук), стан запитів і
  розклад на сьогодні.
- **Налаштування** — режим і статуси, коли надсилати, кому не надсилати,
  посилання й відписка.
- **Інструменти** — тестовий лист на свою адресу, «Поставити в чергу минулі
  замовлення» з попереднім переглядом, «Повернути адресу до листів».
- **Журнал** — останні запити зі станом і причиною, фільтр за станом.
  Повну адресу покупця бачить менеджер із правом на замовлення, решта —
  замасковану. Замовлення без email у журнал не потрапляють: якщо адресу
  допишуть пізніше, замовлення стане в чергу само.

Окреме право доступу для менеджерів.

## Безпека

- Посилання з листа — випадковий 256-бітний токен; у базі лише його SHA-256.
- Адреса з токеном нічого не показує: запит кладеться в сесію (з новим id
  сесії), а браузер одразу йде на адресу без токена. Токен не потрапляє ні в
  історію, ні в `Referer`, ні в аналітику сторінки.
- Відкрите посилання дає доступ до форми 24 години; строк самого посилання —
  60 днів (налаштовується). Невідомий і протермінований токен дають однакову
  відповідь, невдалі спроби обмежує `AttemptLimiter`.
- Кожна форма — POST із CSRF-токеном і перевіркою origin; форма відгуку ще й з
  одноразовим токеном. Приймаються лише позиції свого замовлення, кожна — один
  раз.
- Посилання відписки має власний токен: воно потрапляє в заголовок
  `List-Unsubscribe`, тож форму відгуку не відкриває.
- Відмова з листа перемагає налаштування кабінету: адресу акаунта можна змінити
  без підтвердження, тож кабінет не скасує відмову, підтверджену з пошти.
- Адреса сайту в листах — лише `scheme://host[:port]` і лише домен самого
  магазину з налаштувань оновлення ядра; якщо там порожньо — її задає лише
  менеджер із правом на налаштування сайту. Менеджер із правом лише на модуль не
  перенаправить посилання на чужий сайт.
- Дійсне посилання з листа відкривається завжди; ліміт спроб діє лише на хибні
  токени, тож покупці за спільним проксі не блокують одне одного.
- Два прогони планувальника, що перекрились, не надішлють лист двічі.
- Тестовий лист — не більше 10 за 5 хвилин.
- Відгук за посиланням проходить звичайну модерацію магазину.

## Вимоги

- PHP 8.5+
- [Форк OkayCMS](https://github.com/devSviat/OkayCMS-Fork)
- Планувальник OkayCMS у cron (див. нижче)
- Перевірено на PHP 8.5

## Встановлення

### Варіант 1: Скачування з GitHub

1. Скачайте архів з [останнього релізу](https://github.com/devSviat/ReviewRequests-OkayCMS/releases/latest).
2. Розпакуйте його в `{OkayCMS_root}/Okay/Modules/`.

### Варіант 2: Через Git

```bash
cd {OkayCMS_root}/Okay/Modules/Sviat
git clone https://github.com/devSviat/ReviewRequests-OkayCMS.git ReviewRequests
```

### Результат

```
{OkayCMS_root}/Okay/Modules/Sviat/ReviewRequests/
```

Далі: адмін-панель → Модулі → «Прохання про відгук після покупки» → «Встановити».

### Планувальник

Листи надсилає задача планувальника раз на 15 хвилин. Якщо планувальник ще не
запущено, додайте в cron:

```
* * * * * php {OkayCMS_root}/ok scheduler:run
```

## Налаштування

1. Адмін-панель → Відгуки → «Прохання про відгук» → вкладка «Налаштування».
2. **Позначте статус «виконане»** — той, у якому замовлення у вашому магазині
   вважається виконаним. Поки статус не обрано, модуль нічого не робить.
3. Вкажіть **адресу сайту для посилань у листі** (наприклад
   `https://shop.example`), якщо її не задано в налаштуваннях оновлення ядра.
4. На вкладці «Інструменти» надішліть **тестовий лист** на свою адресу й перегляньте його.
5. Перевірте вкладку «Журнал», а тоді перемкніть режим на **«Надсилати листи»**.

За потреби — затримка, вікно, добовий ліміт, частота на адресу, граничний вік
замовлення, виключення, строк посилання й відписка в один клік.
